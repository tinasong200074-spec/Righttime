# 문제 정의: Righttime

> 상태: **확정 (2026-11-25 사용자 확인)**
> 작성일: 2026-11-25 / 제출 마감: 2026-11-26 오전 10시
> 근거 자료: `docs/research/community-stories.md`(지각하는 쪽), `docs/research/waiting-side-stories.md`(기다리는 쪽)

## 1. 한 문장 요약

지각하는 사람은 약속까지 얼마나 남았는지, 지금 출발해야 하는지를 몸으로 감지하지 못해서, 알람이 울려도 제때 움직이지 못한다.

## 2. 주 사용자

- **대표 사용자:** 20대 후반 직장인. 친구·연인 약속에 자주 10~30분 늦고, 스스로 고치고 싶어 한다. 준비 시간을 짧게 잡고, 준비하다 딴 일에 빠진다.
- **보조 사용자 ①:** ADHD나 시간 감각 부족을 겪는 사람. 같은 기능이 도움이 될 수 있다.
- **보조 사용자 ② (간접):** 기다리는 사람. 전용 화면은 만들지 않고, 지각하는 사람이 보내는 한 줄 알림을 받는 쪽으로만 다룬다.
- **이번에 제외:** 일찍 도착하기 싫어서 일부러 늦는 사람(동기가 다름).
- **다음으로 미룸:** 불안·낮은 자존감 때문에 준비가 길어지는 사람.

## 3. 문제 상황

### 핵심 장면
약속 당일, 준비를 시작해서 현관을 나서기까지(출발 전 1~2시간). 이 구간에서 지각 여부가 갈린다.

### 지각하는 쪽에서 본 원인 (자료에서 반복된 것)
1. **시간 추정 오류:** 준비·이동 시간을 짧게 잡고, 전환에 드는 시간을 과소평가한다.
2. **주의 분산:** 준비하다 다른 일에 빠져 시간이 훌쩍 간다. 시간 감각이 거의 없다는 사람도 있다.
3. **알람 무뎌짐:** 알람을 늘려도 무시하게 된다. 알람 12개에 45분이 걸린다는 사례도 있다.
4. **자책과 숨김:** 늦은 뒤 자기혐오가 들지만 주변에는 숨긴다.

### 기다리는 쪽에서 본 피해 (자료에서 반복된 것)
1. 늦은 시간보다 "내 시간과 약속을 가볍게 본다"는 느낌이 감정의 중심이다.
2. 사전 연락이 없고 사과 없이 넘어가는 것이 화를 키운다.
3. 결과는 약속을 줄이거나, 따로 출발하거나, 연을 끊는 쪽이다.
4. 5~10분은 괜찮고 20분 이상이면 한계로 느끼는 경향이 있다.

### 기존 대안과 약점
| 기존 방법 | 약점 |
|---|---|
| 알람 여러 개 | 무뎌져서 무시하게 된다 |
| 캘린더 알림 | 약속 시각 기준이라 출발 시각을 역산하지 않는다 |
| 출발 시각을 목표로 삼기 | 알려져 있지만 계산과 실천을 스스로 해야 한다 |
| 약속 시각을 앞당겨 알리기 | 들키면 관계가 상한다 |
| 사전 연락 | 늦을 것 같은 순간에 하지 못하고 미룬다 |

## 4. 범위

### 이번에 다루는 것
- 친구·연인 약속의 지각
- 약속 당일 준비 시작 ~ 현관을 나서기까지

### 이번에 하지 않는 것
- ADHD 진단·치료 등 의료 조언
- 지각 벌칙·벌금 제도
- 출근·회의 등 직장 근태 관리
- 약속 시각을 속여 알리는 꼼수 기능
- 일정 자동 취합
- 약속 전날 계획, 이동 중 안내

## 5. 해결 방향 (확정)

- **핵심:** 약속 시각에서 출발 시각을 거꾸로 계산해 주고, 남은 시간을 눈에 보이게 한다.
- **보조:** 알림 강도를 단계적으로 올려 무뎌지지 않게 한다. 지각하는 사람이 "출발했어요/늦을 것 같아요" 한 줄을 상대에게 보낼 수 있게 한다.
- **쓰지 않음:** 알람 개수를 늘리는 방식.
- 구체 기능과 화면은 PRD에서 정한다.

## 6. 성공 기준 (확정)

- **정의:** 약속 시각을 1분이라도 넘기면 지각으로 기록한다.
- **지표:** 10분 이상 지각 횟수.
- **측정 계획:** 사용 전 2주의 자기 기록을 기준값으로 하고, 사용 후 같은 기간과 비교한다. 목표는 10분 이상 지각 횟수를 절반으로 줄이는 것이다.
- **이번 제출:** 시간이 없어 실제 측정은 하지 않고, 시연 시나리오와 측정 계획만 문서로 남긴다.

## 7. 위험과 미확인 가정 (확정)

1. 약속·준비 시간 입력이 귀찮으면 쓰지 않을 수 있다. → PRD에서 "입력 최소화"를 핵심 요구사항으로 한다.
2. 알림이 또 하나의 알람이 되어 무뎌질 수 있다.
3. 일찍 도착하기 싫어서 늦는 사람에게는 효과가 없다.
4. 국내 사용자 맥락이 맞는지 미확인이다. 국내 원문 사연이 부족했고, 해외 사례는 기사와 게시판 요약이다.
5. 주변 사람 3~5명에게 하려던 짧은 확인(1~2일)은 마감 때문에 생략할 가능성이 크다.
