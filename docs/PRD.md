## 1. 요약

도착 시각만 정하면 **이동·준비·기상에 실제로 걸리는 시간**으로 알람과 출발 시각을 거꾸로 정해 주고, 약속 상대에게는 **도착 예정 시각만** 알려 주는 지각 방지 웹앱이다. 기본 흐름은 기상 → 준비 → 출발이다.
> 한 줄 문제정의: 지각하는 사람은 약속까지 얼마나 남았는지, 지금 출발해야 하는지를 몸으로 감지하지 못해서, 알람이 울려도 제때 움직이지 못한다.

## 2. 배경

- 원인(자료에서 반복): 시간 추정 오류, 준비 중 주의 분산, 알람 무뎌짐.
- 기다리는 쪽은 늦는 시간보다 사전 연락이 없는 것에 더 크게 상처받는다.
- 기존 대안(알람 여러 개, 캘린더 알림)은 출발 시각을 역산하지 않고, 실제로 걸린 시간을 반영하지 않는다.
- **하지 않는 선택:** 알람 개수 늘리기, 위치 상시 추적, 준비 단계를 상대에게 문구로 알리기, 문자 자동 발송, 재촉 기능.

## 3. 목표와 지표

| 지표 | 현재 | 목표 | 측정 방법 | 종류 |
|---|---|---|---|---|
| 지각(도착 시각 초과) 횟수 | 미측정 | 사용 전 2주 대비 절반 | 앱의 도착 기록 | 행동 |
| 목표 출발 시각 대비 실제 출발 | 미측정 | 평균 0분 이하 | 기록의 출발 차이 | 행동 |
| 늦을 때 미리 알린 비율 | 미측정 | 제출 시점엔 측정하지 않음 | 후속 | 행동 |

이번 제출의 목표는 효과 측정이 아니라 **측정 수단(기록·통계)과 핵심 흐름이 동작하는 것**이다.

## 4. 대상 사용자

| 세그먼트 | 상황·문제 | 지금 쓰는 방법 | 제약 |
|---|---|---|---|
| 대표: 취준생·직장인 성인 | 면접·약속에 늦지 않아야 하는데 준비 시간을 짧게 잡는다 | 알람 여러 개 | 입력이 귀찮으면 안 쓴다 |
| 보조: 시간 감각이 약한 사람(ADHD 포함) | 시간이 얼마나 흘렀는지 감지하기 어렵다 | 반복 알람, 다이어리 | 알람에 무뎌짐 |
| 간접: 약속 상대 | 언제 오는지 모르고 기다린다 | 메신저로 묻기 | 앱을 깔지 않는다 |

원본 명세의 보호자·아이는 이번 범위에서 뺐다(8장).

## 5. 가치 제안 (대표 세그먼트)

- **Who:** 면접·약속에 늦지 않아야 하는 성인
- **Why:** 제때 도착하고, 늦더라도 상대를 모른 채 기다리게 하지 않고 싶다
- **What before:** 약속 시각만 보고 움직이다 출발을 놓치고, 늦는다는 말을 미룬다
- **How:** 도착 시각 역산, 단계별 타이머, 출발 임박 붉은 조명, 기록 기반 추천, 도착 예정 링크와 한 줄 문구
- **What after:** 나가야 할 순간을 놓치지 않고, 상대는 묻지 않아도 언제 오는지 안다
- **Alternatives:** 알람·캘린더(역산 없음), 지도 앱(준비 시간을 모름), 위치 공유 앱(감시처럼 느껴짐)
- **한 줄:** "약속 시각 말고, 일어날 시각과 나갈 시각을 알려 드려요."

## 6. 화면과 여정 (IA·여정 합침)

### 6.1 화면
| ID | 화면 | 역할 |
|---|---|---|
| S01 | 오늘 | 일정·도착 장소·이동 시간·준비 단계 입력, 기상/준비/출발 시각, 날씨, 챙길 것, 준비 도우미, 알람 켜기 |
| S02 | 기상 | 알람 후 경과 시간, 준비 시작 / 5분 더 |
| S03 | 준비 | 단계별 타이머, 채워지는 막대, 다 했어요 |
| S04 | 출발 | 출발까지 카운트다운, 날씨, 챙겼어요? 목록, 출발했어요 |
| S05 | 이동·도착·요약 | 이동 타이머, 도착(위치 한 번 확인), 기록 저장 |
| S06 | 기록 | 기록을 반영한 알람, 평균, 최근 7일 그래프, 장소별 이동 평균 |
| S07 | 설정 | 알람 값, 말투, 자주 가는 곳, 날씨 기준, 푸시, 시연 모드, 데이터 삭제 |
| S08 | 링크 보기 | 앱 없이 보는 읽기 전용 화면 (도착 예정, 단계) |

하단 탭은 오늘·기록·설정이다. 알람이 울린 뒤부터 기록 저장까지는 S02~S05만 보인다.

### 6.2 핵심 여정 (CUJ-1: 면접 전날부터 도착까지)
1. 도착 시각과 장소를 넣는다. 안내문 사진을 올리면 준비물이 정리된다 (S01).
2. 알람·준비·출발 시각을 확인하고 알람을 켠다 (S01).
3. 알람이 울리면 준비를 시작한다 (S02).
4. 단계를 하나씩 끝낸다. 출발 5분 전부터 화면 가장자리가 붉어진다 (S03).
5. 챙길 것을 확인하고 출발한다 (S04).
6. 늦을 것 같으면 한 줄 문구를 직접 보내거나, 미리 보낸 링크로 상대가 도착 예정을 본다 (S04, S08).
7. 도착을 기록한다. 다음 알람에 이번 기록이 반영된다 (S05, S06).

### 6.3 Moments of Truth
- **MOT-1:** 출발 직전, "지금 나가야 한다"를 놓치지 않는 순간
- **MOT-2:** 늦을 것 같을 때, 망설이지 않고 알리는 순간
- **MOT-3:** 기록이 쌓여 알람이 실제에 맞게 당겨지는 순간

### 7.2 비기능 요구사항
- **저장:** 기록·설정·장소·조회 기록은 기기(`localStorage`)에만 둔다.
- **서버로 가는 것:** 공유를 켰을 때의 단계·도착 예정, 푸시를 켰을 때의 알림 시각과 구독 주소, AI에 보내는 글·사진(전송 전 안내), 카카오에 보내는 검색어·좌표.
- **키:** 서버 함수(`api/`)에만 있다. 브라우저에는 공개돼도 되는 Supabase 주소·anon 키와 푸시 공개 키만 있다.
- **DB 접근:** 표는 잠그고(RLS, 정책 없음) 함수로만 드나든다. 읽기는 토큰, 쓰기는 기기만 아는 쓰기 키가 필요하다.
- **오프라인:** 앱 껍데기는 캐시되어 열린다. 날씨·AI·카카오·공유는 인터넷이 필요하고, 실패해도 핵심 흐름은 동작한다.
- **AI 답 검증:** 길이 제한, 단계 단어 필터, 자리표시자 확인. 안내문은 지시가 아니라 정보로만 읽게 한다.

### 7.3 기술
- Vite + React + TypeScript, PWA(`vite-plugin-pwa`), Vitest, ESLint.
- 서버 함수: Vercel Functions(`api/claude`, `api/kakao`, `api/push-run`).
- DB: Supabase(`shares`, `push_jobs`, 예약 실행 `pg_cron`).
- 외부: Claude(Anthropic SDK, 기본 모델 `claude-opus-5-5`), 카카오맵 REST API, Open-Meteo.
- **ERD:** 서버 표는 두 개뿐이고 서로 관계가 없어 별도 ERD 문서는 생략한다. 설계는 `supabase/migrations/`에 있다.
  - `shares(token, write_hash, name, stage, step_idx, step_count, eta_ms, arrive_ms, late_min, updated_at, expires_at)`
  - `push_jobs(id, endpoint, fire_at)`

### 7.4 가정과 미결

| 구분 | 내용 | 검증 방법 |
|---|---|---|
| 가정 | "평균 + 변동의 절반" 추천이 지각을 줄인다 | 미검증. 2주 사용 기록으로 확인 |
| 가정 | 단계와 도착 예정만 보여도 상대가 안심한다 | 미검증. 사용자 확인 |

| 미결 | 국내 사용자 맥락(원문 사연이 부족했다) | 주변 3~5명 확인 |
| 미결 | "지켰어요"의 기준(몇 분까지 허용) | 지금은 도착 시각 + 0.5분 초과를 늦음으로 본다 |
| 미결 | 실제 기기에서 푸시 수신, 안드로이드 공유창, 아이폰 동작 | 사람이 직접 확인 |
| 미결 | Open-Meteo는 비상업 무료 한도다 | 상업 배포 시 유료 플랜 |
