## 1. 요약

약속 시각에서 **출발 시각을 거꾸로 계산**해 주고, **출발까지 남은 시간을 눈에 보이게** 보여 주며, 알림 강도를 **단계적으로 올리는** 웹앱(PWA)이다. 친구·연인 약속에 자주 늦는 사람이 현관을 제때 나서도록 돕는다.
> 한 줄 문제정의: 지각하는 사람은 약속까지 얼마나 남았는지, 지금 출발해야 하는지를 몸으로 감지하지 못해서, 알람이 울려도 제때 움직이지 못한다.

## 2. 배경

- 원인(자료에서 반복): 시간 추정 오류, 준비 중 주의 분산, 알람 무뎌짐. 기다리는 쪽은 "사전 연락 없음"에 가장 크게 상처받는다.
- 기존 대안(알람, 캘린더 알림)은 무뎌지고, 출발 시각을 역산하지 않는다.
- **이번에 하지 않는 선택:** 알람 개수를 늘리는 방식, 약속 시각을 속이는 기능.

## 3. 목표와 지표

| 지표 | 현재 | 목표 | 측정 방법 | 종류 |
|---|---|---|---|---|
| 10분 이상 지각 횟수 | 사용 전 2주 자기 기록(미측정) | 절반으로 감소 | 앱의 도착 기록(R06, R07) | 행동 |
| 출발 시각 전 알림 확인율 | 없음 | 제출 시점엔 측정하지 않음 | 후속 | 행동 |

- 이번 제출은 실제 효과 측정 없이 **측정 수단(도착 기록과 통계)이 동작**하는 것까지가 목표다.

## 4. 대상 사용자

| 세그먼트 | 상황·문제 | 지금 쓰는 방법 | 제약 |
|---|---|---|---|
| 대표: 20대 후반 직장인 | 친구·연인 약속에 10~30분 늦고 고치고 싶다. 준비 시간을 짧게 잡는다 | 알람 여러 개, 캘린더 알림 | 입력이 귀찮으면 안 쓴다 |
| 보조: 시간 감각이 약한 사람(ADHD 포함) | 시간이 얼마나 흘렀는지 감지하기 어렵다 | 다이어리, 반복 알람 | 알람에 무뎌짐 |

## 5. 가치 제안 (대표 세그먼트)

- **Who:** 친구·연인 약속에 자주 늦는 20대 후반 직장인
- **Why:** 약속에 제때 도착해 상대를 기다리게 하지 않고 싶다
- **What before:** 약속 시각만 보고 움직이다 출발 시각을 놓치고, 알람은 무뎌진다
- **How:** 출발 시각 역산 + 남은 시간 시각화 + 단계적 알림 + 늦을 때 한 줄 알림
- **What after:** 출발해야 할 순간을 놓치지 않고, 늦더라도 미리 알려 관계 손상을 줄인다
- **Alternatives:** 알람·캘린더(역산 없음, 무뎌짐) → Righttime은 출발 시각이 기준이다
- **한 줄:** "약속 시각 말고, 나가야 할 시각을 알려 드려요."

## 6. 사용자 여정과 화면 (IA·여정 합침)

### 6.1 화면 3개 (하단 탭)
| ID | 화면 | 역할 |
|---|---|---|
| S01 | 홈 | 다음 약속의 출발까지 남은 시간, 단계별 상태, "출발했어요/늦을 것 같아요" 보내기 |
| S02 | 약속 추가 | 약속 시각·이동 시간·준비 시간 입력 (4칸 이하) |
| S03 | 기록 | 도착 기록 입력, 10분 이상 지각 횟수, 최근 기록 |

### 6.2 핵심 여정 (CUJ-1: 약속 당일)
1. 약속을 추가한다(S02, 전날 또는 당일 아침).
2. 홈에서 출발 시각과 준비 시작 시각을 본다(S01).
3. 준비 시작 시각이 되면 알림을 받고, 남은 시간이 줄어드는 것을 본다(S01).
4. 출발 시각이 가까워지면 알림이 단계적으로 강해진다(S01).
5. 늦을 것 같으면 "N분 늦을 것 같아요"를 상대에게 보낸다(S01).
6. 약속 후 도착 기록을 남긴다(S03).

### 6.3 Moments of Truth
- **MOT-1:** 출발 시각 직전, "지금 나가야 한다"를 놓치지 않는 순간
- **MOT-2:** 늦을 것 같다고 판단한 순간, 상대에게 한 번에 알리는 순간

### 6.4 사용자 스토리
- 지각하는 사람으로서, 약속 시각만 입력하면 출발 시각을 알고 싶다. (R01, R02)
- 준비하는 중에도 출발까지 남은 시간을 한눈에 보고 싶다. (R03)
- 알림이 무뎌지지 않게 점점 강해졌으면 좋겠다. (R04)
- 늦을 것 같을 때 상대에게 쓸 말을 고민하지 않고 한 번에 보내고 싶다. (R05)
- 내가 얼마나 늦었는지 기록으로 보고 싶다. (R06, R07)

## 7. 솔루션

### 7.1 기능 요구사항

| ID | 요구사항 | 우선순위 | 연결 | 화면 | 수용 기준(판정 가능) |
|---|---|---|---|---|---|
| R01 | 출발 시각 역산 | Must | CUJ-1 #2 | S01 | 약속 18:00, 이동 40분, 여유 10분이면 출발 17:10으로 표시. 준비 30분이면 준비 시작 16:40 |
| R02 | 입력 최소화 | Must | CUJ-1 #1 | S02 | 입력 칸 4개 이하(약속 이름은 선택). 여유 10분·준비 30분 기본값. 마지막 입력값을 다음 기본값으로 쓴다 |
| R03 | 남은 시간 시각화 | Must | MOT-1 | S01 | 출발까지 남은 분을 큰 숫자와 진행 링으로 표시, 1초마다 갱신. 단계(여유·준비 시작·곧 출발·지금 출발·늦음)를 **글자와 색 둘 다**로 표시 |
| R04 | 단계적 알림 | Must | MOT-1 | S01 | 출발 30·15·5·0분 전 알림. 단계가 오를수록 강도가 오른다(배너 크기·진동·소리). 알림 권한이 있으면 시스템 알림도 띄운다 |
| R05 | 한 줄 알림 보내기 | Should | MOT-2 | S01 | "출발했어요", "N분 늦을 것 같아요" 두 버튼. 공유 기능이 있으면 공유창을, 없으면 문구를 복사한다 |
| R06 | 도착 기록 | Must | CUJ-1 #6 | S03 | 약속 시각이 지나면 "몇 분 늦었나요?"를 2탭 이내로 기록(제시간=0분) |
| R07 | 지각 통계 | Must | KR 지표 | S03 | 전체·최근 2주의 10분 이상 지각 횟수와 최근 기록 목록 |
| R08 | 로컬 저장 | Must | 전체 | 전체 | 새로고침·재접속 뒤에도 약속과 기록이 남는다. 서버·계정 없음 |
| R09 | 설치형 웹앱(PWA) | Should | 제출물 | 전체 | 홈 화면에 추가할 수 있고, 인터넷이 없어도 앱이 열린다 |
| R10 | 접근성·반응형 | Must | 전체 | 전체 | 폭 360px에서 가로 스크롤이 없다. 터치 영역 44px 이상. 색에만 의존하지 않는다. 문구는 쉬운 한국어 |

현재 상태: 코드 없음(전부 미구현).

### 7.2 이번에 하지 않는 것 (Non-goals)
계정·서버, 캘린더 연동, 지도 기반 이동 시간 자동 계산, 푸시 서버, 약속 시각을 속이는 기능, 벌칙·벌금, 의료 조언, 출근·회의 근태 관리, 스토어 배포.

### 7.3 비기능 요구사항
- **저장:** 기기 `localStorage`만 사용한다. 개인정보를 서버로 보내지 않는다.
- **오프라인:** R09에 따라 서비스 워커로 앱을 캐시한다.
- **알림 한계:** 서버 없이 만들기 때문에 **앱 탭이 열려 있거나 백그라운드에 있을 때**만 알림이 울린다. 앱을 완전히 닫으면 울리지 않을 수 있다. 시연은 앱을 연 상태로 한다.
- **브라우저:** 최신 모바일 Chrome·Safari. iOS Safari는 홈 화면에 추가해야 시스템 알림이 가능한 제약이 있다.

### 7.4 기술 (승인 대기)
- Vite + React + TypeScript, `vite-plugin-pwa`, Vitest, ESLint. 새 라이브러리라 **설치 전 사용자 승인이 필요하다.**
- 구조: `src/domain`(순수 계산, 테스트 먼저) ← `src/features`(화면) ← `src/infra`(저장·알림).
- **ERD 생략:** 서버와 DB가 없고, 약속과 도착 기록 두 가지를 기기에만 저장하기 때문이다. 자료형은 `src/domain/types.ts`에서 정한다.

### 7.5 가정과 미결

| 구분 | 내용 | 검증 방법 |
|---|---|---|
| 가정 | 입력 4칸이면 귀찮지 않다 | 시연 때 약속 추가에 걸리는 시간을 잰다 |
| 가정 | 단계적 알림이 알람보다 덜 무뎌진다 | 제출 시점엔 미검증. 후속 사용자 확인 |
| 가정 | 한 줄 알림은 공유창·복사로 충분하다 | 시연 확인 |
| 미결 | 국내 사용자 맥락 | 주변 3~5명 확인(마감으로 생략 가능성 큼) |
| 미결 | 웹 배포 계정·프로젝트 | 배포 전 사용자 승인 |

## 8. 릴리즈

- **제출 범위:** R01~R10 중 Must를 우선 완성하고, Should(R05, R09)는 시간 순서대로 넣는다.
