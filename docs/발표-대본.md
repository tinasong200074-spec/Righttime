## 1부. 왜 시작했나

### 1. 표지

안녕하세요. 제때를 소개할게요. 제때는 약속 시각이 아니라, 일어날 시각과 나갈 시각을 알려 주는 앱이에요. 안드로이드에 설치해서 쓰시면 돼요.

`[채울 것: 자기소개 한 줄]`

### 2. 알람은 울렸는데, 왜 또 늦었을까요

알람은 분명 울렸는데 또 늦었던 적 있으시죠? `[채울 것: 내가 이 주제를 고른 계기. 예: 내 경험이나 주변 사람 이야기 한두 문장]`

사연을 모아 보니 이유는 보통 세 가지였어요. 준비와 이동 시간을 짧게 잡아요. 준비하다 딴 일에 빠져요. 그리고 알람이 무뎌져서 안 들려요. 오른쪽은 커뮤니티에 올라온 사연 하나인데요, 알람을 열두 개 맞추고도 일어나는 데 45분이 걸린다는 이야기예요.

다만 해외 사례 위주라서 우리나라 통계는 아니에요.

### 3. 문제 정의

저희가 정리한 문제는 한 문장이에요. 지각하는 사람은 약속까지 얼마나 남았는지, 지금 출발해야 하는지를 몸으로 느끼지 못해요. 그래서 알람이 울려도 제때 움직이지 못하죠.

대표 사용자는 면접이나 약속에 늦으면 안 되는 취준생과 직장인이에요. 시간 감각이 약한 분들에게도 도움이 될 수 있고요. 약속 상대는 앱 없이 링크로 도착 예정과 준비 단계를 봐요.

지각이 갈리는 구간은 알람이 울린 뒤부터 현관을 나서기까지예요. 제때는 이 구간만 다뤄요.

### 4. 지금 쓰는 방법으로는 왜 부족할까요

그럼 지금 쓰는 방법은 뭐가 부족할까요? 알람을 여러 개 맞추면 점점 무뎌져요. 캘린더 알림은 약속 시각에 울리니까 나갈 시각은 알 수 없고요. 지도 앱은 내 준비 시간을 몰라요. 위치 공유 앱은 상대가 감시당하는 느낌을 받죠.

그리고 기다리는 사람은 늦은 시간 자체보다 연락 없이 기다린 것을 더 서운해해요.

## 2부. 제때가 하는 일

### 5. 그래서 제때는 이렇게 해요

그래서 저희가 만든 게 제때예요. 하는 일은 네 가지고요. 도착 시각에서 거꾸로 계산해 알람, 준비, 출발 시각을 대신 정해 줘요. 알람은 앱을 닫아도 울리고요. 남은 시간은 눈에 보이게 해요. 그리고 내가 실제로 걸린 시간을 기억했다가 다음 알람을 다시 잡죠.

### 6. 도착 시각만 정하면 나머지는 거꾸로 계산해요

먼저 거꾸로 계산부터 볼게요. 도착 시각만 정하면 나머지가 정해져요. 아홉 시 도착이면 여덟 시 이십 분엔 출발해야 하죠. 그러려면 일곱 시 사십 분엔 준비를 시작해야 하고요. 그래서 알람은 일곱 시 삼십 분이에요.

이동 시간은 카카오 지도로 자동 계산해요. 오른쪽이 실제 오늘 화면이고요.

### 7. 앱을 닫아도 울리는 알람

다음은 알람이에요. 알람을 켜면 휴대폰에 직접 예약해 두기 때문에 앱을 꺼도, 인터넷이 없어도 울려요. 출발 삼십 분, 십오 분, 오 분 전에도 알려 주고요. 다만 소리는 휴대폰의 알림 음량을 따라요.

`[채울 것: 처음엔 웹앱이라 화면이 열려 있을 때만 울렸고, 그래서 안드로이드 앱으로 바꾼 이야기를 넣을지]`

### 8. 남은 시간이 눈에 보이는 준비

준비하는 동안에는 출발까지 남은 시간을 타이머와 막대로 보여 줘요. 출발 삼십 분, 십오 분, 오 분 전에 알려 주고, 오 분 전부터는 화면 가장자리가 붉게 빛나요. 준비가 끝나면 버튼 하나만 누르면 돼요.

### 9. 내 습관에 맞춰지는 알람

네 가지 중 마지막은 내 습관에 맞춰지는 알람이에요. 시작, 준비, 이동에 실제로 걸린 시간을 기록해서 다음 알람에 반영해요. 달력으로도 보여 주고요. 화면의 숫자는 샘플 기록 예시인데요, 이 경우엔 알람이 서른다섯 분 빨라요.

### 10. 챙길 것도, 매일 쓰는 것도 쉽게

자잘한 것도 챙겨 줘요. 챙길 체크리스트를 적어 두면 출발 단계로 넘어갈 때 소리와 함께 '이거 챙겼어?' 하고 물어봐요. 날씨에 맞춰 우산과 겉옷도 더해 주고요. 안내문 사진이나 링크를 넣으면 AI가 준비물을 정리해 줘요. 약속은 여러 개 잡아 둘 수 있고, 요일마다 반복할 수도 있어요.

### 11. 기다리는 사람을 배려해요

약속에는 기다리는 사람도 있죠. 제때는 도착 예정 시각과 준비 단계만 알려요. 말투는 네 가지와 내 말투 중에서 골라요. 링크로 앱 없이 볼 수 있고, 친구를 골라 두면 알람이 울릴 때 바로 공유돼요. 친구는 한마디와 이모티콘으로 답할 수 있어요.

반대로 올리지 않는 것도 정했어요. 위치, 알람 미루기, 혼자 잡은 약속 기록은 올리지 않아요. 조회 여부 표시나 문자 자동 발송, 위치 상시 추적도 하지 않아요.

## 3부. 문제가 어떻게 풀리나

### 12. 이 기능들을 왜 넣었나요

기능을 하나씩 보여 드렸는데요, 왜 이것들을 넣었는지 앞의 문제와 짝지어 볼게요.

| 문제 | 그래서 넣은 기능 | 어떻게 풀리나 |
|---|---|---|
| 준비·이동 시간을 짧게 잡는다 | 도착 시각에서 거꾸로 계산, 기록으로 보정 | 내가 어림한 시간이 아니라 실제로 걸린 시간으로 알람이 잡혀요 |
| 준비하다 딴 일에 빠진다 | 남은 시간 타이머, 출발 전 알림, 붉은 조명 | 남은 시간이 계속 보이고, 출발이 가까우면 화면이 먼저 알려요 |
| 알람이 무뎌진다 | 닫아도 울리는 알람을 일어날 시각에 맞춤 | 알람을 여러 개 맞추는 대신, 필요한 시각에 한 번 울려요 |
| 기다리는 사람이 연락 없이 기다린다 | 도착 예정과 준비 단계를 링크로 공유 | 따로 연락하지 않아도 상대가 지금 상태를 볼 수 있어요 |

읽을 말:

시간을 짧게 잡는 문제는 거꾸로 계산과 기록 보정으로 풀어요. 내가 어림한 시간이 아니라 실제로 걸린 시간으로 알람이 잡히거든요. 딴 일에 빠지는 문제는 남은 시간 타이머와 출발 전 알림, 붉은 조명이 맡아요. 알람이 무뎌지는 문제는 알람을 여러 개 맞추는 대신, 닫아도 울리는 알람을 일어날 시각에 맞췄어요. 그리고 기다리는 사람이 연락 없이 기다리지 않게 도착 예정과 준비 단계를 링크로 알려요.

## 4부. 어떤 도구와 스킬로 무엇을 만들었나

### 13. 만든 과정

만드는 과정도 문서로 남겼어요. 순서는 조사, 문제 정의, 요구사항, 구현과 테스트, 제출 전 점검이에요.

| 단계 | 쓴 스킬·도구 | 만든 것 |
|---|---|---|
| 조사 | 웹 검색 | 지각하는 쪽·기다리는 쪽 커뮤니티 사연 2종 (`docs/research/`) |
| 문제 정의 | 인터뷰 스킬(grilling) | 문제 정의서: 원인 3가지, 하지 않을 것, 성공 기준 |
| 요구사항 | PRD 스킬(prd) | 화면 구조와 사용자 여정을 합친 요구사항 문서, 요구사항 25개 |
| 구현 | 최소 변경 스킬(ponytail), 자동 테스트(Vitest) | 앱 코드, 자동 테스트 167개 통과 |
| 점검 | QA 스킬(qa), 내장 브라우저 | 점검표: 제가 확인한 82개 중 72개 통과, 나머지는 휴대폰에서 직접 확인 |
| 발표 자료 | PPT 스킬(pptx), 윤문 스킬(humanize-korean) | 이 발표 자료와 대본 |

읽을 말:

먼저 지각하는 쪽과 기다리는 쪽의 사연을 조사했고, 인터뷰 스킬로 질문을 주고받으며 문제 정의서를 썼어요. 그다음 PRD 스킬로 요구사항 문서를 만들었는데 요구사항이 스물다섯 개예요. 코드를 쓸 때는 꼭 필요한 만큼만 고치게 하는 스킬을 먼저 거쳤고, 자동 테스트 백예순일곱 개를 돌렸어요. 마지막으로 QA 스킬로 점검표를 만들었는데요, 제가 확인한 여든두 개 중 일흔두 개가 통과했어요. 나머지는 휴대폰에서 직접 확인해야 해요.

`[채울 것: 문서를 먼저 쓰고 코드를 쓴 것이 실제로 도움이 된 순간 하나]`

### 14. 쓴 기술

어떤 기능을 무엇으로 만들었는지 정리하면 이래요.

| 기능 | 쓴 도구 | 한 줄 설명 |
|---|---|---|
| 안내문 사진·링크 읽기, 메모 정리, 내 말투 | Claude API | 서버에서만 불러요. 링크는 웹 가져오기 도구로 읽어요 |
| 장소 검색, 대중교통 이동 시간 | 카카오 지도 API | 처음 가는 곳은 넉넉하게 잡고, 알람 뒤에 다시 조회해요 |
| 우산·겉옷 추천 | Open-Meteo | 출발부터 도착까지의 시간별 예보로 정해요 |
| 친구와 공유, 링크 공유, 한마디·이모티콘, 기기 계정 | Supabase | 표는 직접 못 읽게 막고, 정해 둔 함수로만 주고받아요 |
| 앱을 닫아도 오는 알림 | 웹 푸시 | 웹앱에서 써요 |
| 닫아도 울리는 알람 | Capacitor(안드로이드 앱) | 알람 시각을 휴대폰에 직접 예약해요 |
| 화면, 계산 규칙 | React + TypeScript | 계산 규칙은 화면과 떼어 두고 테스트를 먼저 썼어요 |
| 배포 | Vercel | GitHub에 올리면 자동으로 배포돼요 |

읽을 말:

안내문 사진과 링크 읽기, 말투 만들기는 Claude API를 서버에서만 불러요. 장소 검색과 이동 시간은 카카오 지도, 날씨는 Open-Meteo가 맡고요. 친구와 공유하는 부분과 링크 공유는 Supabase예요. 앱을 닫아도 오는 알림은 웹 푸시, 닫아도 울리는 알람은 Capacitor로 만든 안드로이드 앱이 맡아요. 비밀 키는 서버에만 두고 화면에는 내려보내지 않았어요.

`[채울 것: 이 가운데 처음 써 본 도구와 느낀 점]`

### 15. 구현과 일하는 방식

폰 기능으로는 알람 소리와 진동, 알림창, 도착 위치 한 번 읽기, 홈 화면 설치, 사진 공유 받기를 썼어요.

만들 때는 Claude Code 창 세 개가 역할을 나눠 같이 작업했어요. 한 창은 서버와 공유, 한 창은 아침 진행 화면, 한 창은 오늘·기록·설정 화면을 맡았어요. 문서 단계마다 확인을 받았고 코드를 쓰기 전에는 최소 변경 스킬을 거쳤어요. 배포나 키 입력처럼 되돌리기 어려운 일은 먼저 물어보게 했고요.

| 일한 방식 | 쓴 것 | 왜 |
|---|---|---|
| 창 3개가 동시에 작업 | Claude Code 창 3개, 각자 자기 파일만 커밋 | 서로 덮어쓰지 않으면서 빨리 만들려고 |
| 규칙을 문서로 고정 | `CLAUDE.md`(하네스) | 창이 달라도 같은 규칙을 따르게 하려고 |
| 서버 변경·배포 | Supabase·Vercel 연결(MCP) | 적용 전에 항상 저에게 묻게 했어요 |
| 화면 확인 | 내장 브라우저 | 고친 화면을 직접 열어 눌러 보게 했어요 |

`[채울 것: AI와 일하면서 사람이 꼭 확인해야 했던 지점. 예: 웹앱으로는 닫힌 상태에서 알람 소리가 안 난다는 한계를 직접 발견한 일]`

## 5부. 성공 기준, 한계, 마무리

### 16. 성공은 이렇게 따져요

그럼 성공 기준은요? 도착 시각에서 30초만 넘겨도 지각으로 기록해요. 목표는 사용 전 2주와 비교해 지각 횟수를 절반으로 줄이는 거고요.

다만 이번엔 시간이 없어서 실제 측정은 하지 못했어요. 측정할 기록 기능과 계획까지만 만들었어요. 국내 사용자 확인과 추천 규칙 검증도 앞으로 할 일이에요.

### 17. 알아 둘 점

알아 둘 점도 말씀드릴게요. 닫아도 울리는 알람은 안드로이드 앱에서만 돼요. 아이폰은 웹앱으로 쓰셔야 하고요. 무음이나 방해금지 모드면 울리지 않아요. 그리고 지금은 시험용 설치 파일이에요. 에뮬레이터에서는 확인했지만 실제 휴대폰 확인과 스토어 등록은 아직이에요.

`[채울 것: 실제 휴대폰에서 직접 확인한 것이 있으면 여기서 고쳐 말하기]`

### 18. 약속 시각 말고, 나갈 시각

마무리할게요. 제때가 알려 드리는 건 약속 시각 말고 나갈 시각이에요. 다음으로는 스토어 등록과 아이폰 앱을 준비하고 있어요. 도착 시각 기준 이동 시간도요. 지각이 얼마나 줄었는지는 써 보면서 앞으로 확인할 거예요.

오른쪽 QR로 설치해 보실 수 있어요. 이제 시연을 보여 드릴게요.

## 6부. 시연

시연에서 보여 줄 정상 사례·예외 사례와 화면 여는 순서는 [시연 가이드](시연-가이드.md) 4장에 있습니다.

### 19. 시연 ① 아침 한 바퀴

첫 시연은 아침 한 바퀴예요. 시연 모드에서는 1초가 1분처럼 흘러서 알람, 준비, 출발, 도착, 기록까지 아침 전체를 1~2분 안에 볼 수 있어요. 출발이 가까워지면 붉은 조명이 켜지는 것도 보실 수 있고요.

`[채울 것: 시연하면서 짚을 말. 예: "지금 가장자리가 붉어졌죠, 출발 5분 전이에요"]`

### 20. 시연 ② 닫아도 울리는 알람

이번엔 닫아도 울리는 알람이에요. 알람을 2분 뒤로 맞추고 앱을 닫은 다음 기다려 볼게요. 앱이 꺼져 있어도 시간이 되면 울릴 거예요.

`[채울 것: 기다리는 2분 동안 할 말. 예: 12번 슬라이드의 문제와 해결을 다시 짚기, 또는 질문 받기]`

감사합니다.
