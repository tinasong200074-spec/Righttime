# 시연 가이드: 제때 (Righttime)

발표 자료(PPT)와 최종 시연을 준비할 때 보는 문서. 아래 실행 결과는 2026-11-26에 실제로 돌려서 나온 값이다. 같은 날 추가한 것(설치 앱, 약속 여러 개, 기록 분석·달력, 처음 가는 곳 넉넉하게)까지 반영했다.

- 배포 주소: https://righttime-alpha.vercel.app
- 저장소: https://github.com/tinasong200074-spec/Righttime
- 안드로이드 설치 파일: https://github.com/tinasong200074-spec/Righttime/raw/main/apk/jette.apk

## 1. 한 줄 소개

> 지각하는 사람은 약속까지 얼마나 남았는지, 지금 출발해야 하는지를 몸으로 감지하지 못해서, 알람이 울려도 제때 움직이지 못한다.

**제때**는 도착 시각만 정하면 이동·준비·시작시간에 실제로 걸리는 시간으로 알람과 출발 시각을 거꾸로 정해 주고, 약속 상대에게는 도착 예정 시각만 알려 주는 지각 방지 웹앱이다. 안드로이드는 앱을 닫아도 알람이 울리는 설치 앱도 있다.

| R10 | 일정 준비 도우미 | 안내문 글·사진·링크를 AI가 읽고 준비물·시각을 정리한다 |
| R11 | 내 말투, 메모 나누기 | 내 말투 예시로 문구를 만들고, 긴 메모를 항목으로 나눈다 |
| R12 | 장소·대중교통 | 카카오로 장소를 찾고 대중교통 시간을 가져온다 |
| R13 | 이동 시간 보정 | 알람이 울린 뒤 다시 조회하고, 비슷한 시간대의 과거 조회값을 쓴다. 처음 가는 곳은 넉넉하게 잡는다(40분 → 50분) |
| R14 | 링크 공유 | 앱 없이 볼 수 있는 준비 현황 링크. 한 번 보낸 뒤에는 "공유 끄기"만 남는다 |
| R15 | 사진 공유 받기 | 갤러리에서 "공유 → 제때"로 사진을 보낸다(안드로이드) |
| R16 | 푸시 알림 | 앱을 닫아도 시작시간·출발 알림이 온다 |
| R17 | 접근성·반응형 | 44px 터치 영역, 360px에서 가로 스크롤 없음, 색만으로 알리지 않음 |
| R18 | 친구 약속 방 | 초대 코드로 모여 서로의 단계와 도착 예정을 본다. 초대받은 사람에게는 "방에서 나가기"만 보인다 |
| R19 | 최근 일정 | 다시 열면 비우고, 최근 일정을 눌러 다시 채운다 |
| R20 | 요일 반복 | 고른 요일마다 알람이 다시 켜진다 |
| R21 | 장소 검색·즐겨찾기·집 | 출발·도착 칸을 누르면 바로 검색하거나 지난 검색에서 고른다. 즐겨찾기는 맨 위, 집은 작은 버튼 하나. 출발지는 기본으로 지금 위치 |
| R22 | 약속 여러 개 | 알람이 켜진 약속을 둔 채 새 약속을 더 잡는다. 가장 이른 약속이 맨 앞, 끝나면 다음 약속이 올라온다 |
| R23 | 안드로이드 설치 앱 | 앱을 닫아도 알람 소리와 알림이 나온다. 처음 열 때 알림·위치 권한을 묻는다 |
| R24 | 기록 분석·달력 | 큰 숫자 타일과 한 줄 조언, 날짜별 제시간(✅)·지각(⏰) 달력 |
| R25 | 친구를 골라 바로 공유 | 새 약속에서 친구를 고르면 알람을 켤 때 바로 공유된다. 친구가 다음 단계로 넘어가면 맨 위에 5초 알림 |

**기술 구성**
- 화면: React + TypeScript 웹앱(PWA). 하단 탭은 오늘·기록·새 약속·친구·설정. 3층 구조(`domain` ← `features` ← `infra`)
- 서버: Vercel 함수 3개(`api/claude`, `api/kakao`, `api/push-run`)
- AI: Claude API(글·사진 읽기, 말투, 메모 나누기). 키는 서버에만 있다
- DB: Supabase 표 4개(`shares`, `push_jobs`, `rooms`, `room_members`). 모두 직접 접근을 막고 정해진 함수로만 읽고 쓴다
- 안드로이드 설치 앱: Capacitor로 웹앱을 감싸고, 알람만 휴대폰에 직접 예약한다
- 테스트: 도메인 규칙 테스트 167건

## 4. 시연: 정상 사례와 예외 사례

**실행 방법 (터미널에서 그대로 보여 줄 수 있다)**

```
npm run demo:cases
npm run demo:api
```

- `demo:cases`: 앱이 쓰는 계산 함수를 그대로 불러 결과를 찍는다(`src/cases.demo.test.ts`).
- `demo:api`: 배포된 AI 서버에 실제로 요청을 보낸다(`demo/api-cases.py`). 한 번에 Claude 호출 2회가 나간다.

### 4.1 정상 사례

| # | 입력 | 실행 결과 | 해결 방식 | 판단 근거 | 사람이 확인하는 지점 |
|---|---|---|---|---|---|
| 정상1 | 09:00 도착, 이동 30분, 여유 10분, 준비 40분, 시작시간 10분. 기록 없음 | 알람 07:30 · 준비 시작 07:40 · 출발 08:20 | 도착 시각에서 이동+여유 → 준비 → 시작시간 순으로 뺀다 | 기록이 없으므로 "내 입력값"을 그대로 쓴다고 화면에 표시 | 알람 켜기 버튼은 사람이 누른다 |
| 정상2 | 같은 일정 + 기록 5회(준비 45~55분, 시작시간 12~20분) | 알람 **07:10** · 준비 시작 07:28 · 출발 08:20. 준비 52분, 시작시간 18분 | 입력값(40분) 대신 실제 기록으로 다시 계산 | "최근 5회 평균 + 변동 반영". 평균보다 조금 넉넉하게 잡는다 | 추천값과 근거를 화면에 보여 주고, 사람이 그대로 쓸지 정한다 |
| 정상3 | 도착이 약속보다 7분 일찍 / 정각 / 3분 늦음 | 일찍 / 제시간 / 늦음 | 약속 시각과의 차이로 판정 | 30초 넘게 늦으면 늦음, 5분 넘게 이르면 일찍 | 도착 버튼은 사람이 누른다. 위치 확인은 동의했을 때 한 번만 |
| 정상4 | AI에게 메모 "우산 챙기고 가스 잠갔는지 확인, 노트북 충전기" | 3개 항목과 질문으로 나뉨: 우산 / 가스 잠금 확인 / 노트북 충전기 | Claude가 항목과 "챙겼어?" 질문으로 나눈다 | 서버가 결과 모양을 다시 검사해 정해진 형식만 통과시킨다 | 나뉜 결과는 사람이 체크한 것만 담긴다 |

### 4.2 예외 사례

| 예외2 | 시연 기록·제외한 기록만 5회 | 알람 07:30 그대로. 근거 "내 입력값" | 시연과 제외 기록은 추천에 쓰지 않는다 | 가짜 데이터가 실제 알람을 바꾸면 안 된다 | 기록 화면에서 사람이 "이 날은 빼기"를 고른다 |

| 예외4 | 도착 시각이 이미 지남 | 다음 날 같은 시각으로 넘김 | 지난 시각에 알람을 걸지 않는다 | 지난 약속은 울릴 수 없다 | 도착 날짜는 오늘 화면 맨 위에 나온다. 사람이 날짜를 확인한다 |
| 예외14 | 준비 + 이동이 도착 시각을 넘김(40분 뒤 약속, 준비 52분 + 이동 30분) | "알람 켜기"가 막히고 "도착 시각보다 43분 넘어요" | 맞출 수 없는 약속에는 알람을 켜지 않는다 | 지금 바로 시작해도 늦는지만 본다 | 사람이 도착 시각을 늦추거나 시간을 줄인다 |
| 예외5 | 한 번 크게 늦은 날(준비 40, 42, 41, **120**, 43분) | 추천 75분 | 변동이 크면 넉넉하게 잡는다 | 평균 + 변동의 절반. **이 규칙은 검증되지 않은 임의 규칙이라 한계로 적어 둠** | 이상한 날은 사람이 기록에서 빼야 한다. 빼면 예외2처럼 계산에서 빠진다 |
| 예외6 | 대중교통 응답이 비었거나 깨짐, 좌표가 범위 밖 | 결과 없음(null), 좌표 거부 | 깨진 값을 쓰지 않는다 | 형식 검사를 통과한 값만 쓴다 | 사람이 이동 시간을 직접 넣는다 |
| 예외7 | 초대 코드 오타(`AB0CD1`, `abc`) | 거부. `k7m-9pq`는 `K7M9PQ`로 고쳐서 통과 | 헷갈리는 글자(0, 1, O, I)는 코드에 쓰지 않는다 | 소문자·하이픈은 사람 실수라 고쳐 주고, 없는 글자는 거부 | 사람이 코드를 다시 확인 |
| 예외8 | 공유 상태가 20분째 그대로 | "확인 안 됨"으로 표시(3분 전은 정상) | 오래된 값을 지금 값처럼 보여 주지 않는다 | 앱을 닫았거나 인터넷이 끊겼을 수 있다 | 보는 사람이 "지금과 다를 수 있음"을 알고 직접 연락 |

### 4.3 앱 화면에서 직접 보여 줄 순서 (약 5분)

화면은 4.4의 "브라우저 창 2개" 방법으로 띄운다. 왼쪽 창이 나, 오른쪽 창이 친구(약속 상대)다.

1. **정상 흐름**: "새 약속" 탭에서 일정 이름, 도착 시각, 장소를 넣는다 → 맨 아래에 "이동 + 준비 = 총 시간"과 "몇 시에 시작해야 하는지"가 바로 계산된다 → 알람을 켠다 → 오늘 화면 맨 위 검은 카드에 일정 이름, 도착 시각, 거꾸로 계산된 시작시간(알람)이 크게 나온다. "챙길 체크리스트"를 눌러 챙길 것을 적는다.
2. **시연 모드**: 설정 → "시연 모드·데이터"에서 시연을 시작해 시작시간 → 준비 → 출발 → 도착까지 진행한다. 출발 직전에 붉은 조명이 켜지고, "준비 끝났어요"를 눌러 출발 단계로 넘어가면 소리와 함께 "이거 챙겼어?"가 뜬다(체크리스트에 적어 둔 것이 있을 때).
3. **기록으로 바뀌는 알람**: 설정 → "시연 모드·데이터" → "샘플 데이터 넣기" → 기록 탭. "알람이 N분 빨라요", 숫자 타일(눈여겨볼 것은 검은 바탕 + `!`), 조언 한 줄, 달력의 ✅·⏰를 보여 주고 날짜 하나를 눌러 그날 일정을 연다.
4. **약속 여러 개**: 알람을 켠 채 "새 약속" 탭 → "새 약속 추가하기" (알람이 켜져 있어도 바로 적을 수 있다) → 하나 더 잡는다 → 오늘 화면에는 가장 가까운 일정만 크게 나오고, 나머지는 그 아래에 작게 나열된다.
5. **상대에게 알리기**: 문구가 하나만 나오는 것을 보여 준다. **보내기는 사람이 누른다.** 앱이 대신 보내지 않는다.
6. **링크 공유(예외 포함)**: (오늘 화면 위쪽의 공유 줄을 ✕로 닫은 적이 있으면 나오지 않는다. 그때는 7번 친구 방으로 보여 준다) 왼쪽 창에서 공유를 켜고 링크를 보낸다 → "공유 끄기"만 남는 것을 보여 준다 → 오른쪽 창에서 링크를 연다 → 왼쪽에서 공유를 끄면 오른쪽이 "링크가 닫혔어요"로 바뀐다.
7. **친구 방(예외 포함)**: 왼쪽 창에서 방을 만든다 → 오른쪽 창에서 틀린 코드를 넣어 거부되는 것을 보여 준 뒤, 맞는 코드로 들어간다 → 서로의 단계가 보인다. 초대받은 쪽에는 "방에서 나가기"만 있다.
8. **AI 예외**: 일정 준비 도우미에 숨은 지시가 든 글을 넣는다 → 준비물만 나오고, 체크한 것만 담긴다.
9. **(터미널) 사례 실행**: `npm run demo:cases`로 정상 3건·예외 8건의 계산 결과를 그대로 보여 준다.

## 5. 사람의 확인이 필요한 지점 (정리)

**앱 안에서**
- AI가 정리한 준비물·날짜·시각은 사람이 체크하거나 눌러야 반영된다. 자동으로 일정을 바꾸지 않는다.
- 글과 사진은 "읽고 정리하기"를 눌러야 AI로 전송된다. 받은 즉시 보내지 않는다.
- 상대에게 보내는 문구는 만들어 주기만 하고, 보내는 것은 사람이다.
- 준비 현황 공유는 사람이 켜고 끈다. 위치·미루기·기록은 어떤 경우에도 보이지 않는다.
- 위치는 도착했을 때 동의한 경우에만 한 번 확인하고 저장하지 않는다.
- 추천값에는 항상 근거 문구가 붙는다. 이상한 날의 기록은 사람이 뺀다.
- 처음 가는 곳의 이동 시간은 넉넉하게 잡고 이유를 화면에 적는다. 알람이 울린 뒤 앱을 열면 다시 조회해 출발 시각을 고치고 알려 준다.
- 설치 앱은 처음 열 때 알림·위치 권한을 사람에게 묻는다. 거절해도 앱은 동작한다.

**만드는 과정에서 (Claude Code와 일한 방식)**
- `CLAUDE.md`에 "항상 먼저 물음" 목록을 정했다: GitHub push, 배포, 파일·데이터 삭제, 새 라이브러리 설치, DB 변경, 키 입력.
- 문서(문제 정의 → PRD)는 단계마다 사용자 확인을 받고 다음으로 넘어갔다.
- Claude가 확인하지 못한 것은 "확인하지 못했다"로 적었다(QA 시트의 No Run 7건, 직접 QA 22건).
- Claude Code 창 3개가 역할을 나눠 같은 폴더에서 작업했다(계산·서버 / 아침 화면 / 나머지 화면).

## 6. 알려진 한계

- 웹앱은 닫혀 있으면 알람 소리가 나지 않는다. 푸시 알림만 오고 최대 1분 늦을 수 있다. 알람을 켤 때 휴대폰 시계 알람도 맞추라고 안내한다.
- 안드로이드 설치 앱(`apk/jette.apk`)은 앱을 닫아도 알람이 울린다(에뮬레이터에서 확인, 실제 휴대폰은 미확인). 소리는 알림 음량을 따라서 무음·방해금지면 나지 않는다. 아이폰용 설치 앱은 없다.
- 카카오 대중교통 시간은 "지금 출발" 기준이고 시간대별 평균은 알 수 없다. 처음 가는 곳은 4분의 1을 더해 넉넉하게 잡는데, 이 비율은 어림값이다.
- 추천 규칙(평균 + 변동의 절반)은 검증되지 않았다. 예외5처럼 한 번의 큰 값에 끌려간다.
- 약속 여러 개는 진행이 한 번에 하나다. 링크 공유와 친구 방은 맨 앞 약속에만 연결된다.
- 친구 기능은 로그인 없이 기기 계정을 쓴다. 휴대폰을 바꾸면 친구 목록이 이어지지 않는다.
- 사진 공유 받기는 앱을 설치한 안드로이드에서만 된다.
- 실제 휴대폰에서의 푸시 수신, 휴대폰 두 대의 친구 방, 설치 앱의 알람은 사용자 확인이 남아 있다.

## 7. 발표 자료(PPT)에 반영할 변경

발표 자료를 먼저 만들었다면 아래를 맞춘다.

| 바꿀 곳 | 예전 | 지금 |
|---|---|---|
| 용어 | 기상 | 시작시간 (아침에만 쓰는 앱이 아니라서) |
| 제품 형태 | 웹앱(PWA) | 웹앱 + 안드로이드 설치 앱(APK). 아이폰은 웹앱 |
| 하단 탭 | 오늘·기록·설정 | 오늘·기록·새 약속·친구·설정 |

| 알리는 문구 | 도착 시각 / 늦을 것 같을 때 두 칸 | 하나만. 출발 시각이 지나 늦을 것 같을 때만 늦는다는 문구 |
